### `TCalendar.py`

**Изменение 1 — вызов `CalcMoonTimes`:**
Старый вариант передавал объекты `mp.moonrise` и `mp.moonset` как out-параметры и оборачивал `mp.hasDST` в `double()`:

```python
mp.moonrise, mp.moonset = CalcMoonTimes(earth, mp.date, mp.hasDST)
```
Это изменение интерфейса функции расчёта времён восхода/захода луны — убран `double()` wrapper и изменена сигнатура вызова. **Затрагивает логику получения лунных времён** (см. раздел ниже).

**Изменение 2 — баг-фикс:**
Исправлена неверная ссылка `GCDS.CAL_MOON_SET` → `CAL_MOON_SET`. Без этого фикса время захода луны не отображалось из-за обращения к несуществующему атрибуту.

## Коммит `fd8d744` — Check sandhyas

### `TToday.py`
**Баг-фикс форматирования строк (3 места):**
Было: `stream.write(" sandhya {} - {} ", tda.short(-24), tda.short(24))`
Стало: `stream.write(" sandhya {} - {} ".format(tda.short(-24), tda.short(24)))`

В Python метод `.write()` не принимает дополнительные аргументы как `printf` — без `.format()` аргументы молча игнорировались и в вывод шла буквальная строка `"{} - {}"`. Это баг-фикс отображения сандхьи.

**Тестовая локация:** изменена с Братиславы (`48.15°N, 17.11°E`) на Липецк (`52.61°N, 39.60°E`).

**Вывод в файлы:** закомментированы вызовы записи в RTF и HTML в тестовом блоке.

Все изменения касаются тестового/отладочного кода и форматирования вывода.

# ИЗМЕНЕНИЯ ЛОГИКИ РАСЧЁТОВ

Обнаружено **2 изменения**, затрагивающих логику расчётов:

## 1. Коммит `a25b426` / `TCalendar.py` — смена интерфейса `CalcMoonTimes`

Изменён способ вызова функции расчёта времён восхода/захода луны: с передачи out-параметров на получение через return-значения. Дополнительно убран `double()` wrapper над `mp.hasDST`, который ранее явно приводил тип DST-флага.

**Влияние:** при смене сигнатуры `CalcMoonTimes` фактически изменилась и реализация самой функции. Если раньше функция модифицировала переданные объекты напрямую, теперь она возвращает новые значения. Возможна разница в поведении при граничных случаях (DST, полярные зоны).

## 2. Коммит `0332620` / `TCalendar.py` — отключение расчёта санкранти

Добавлен ранний `return`, который прерывает выполнение `CalculateCalendar()` после расчёта базовых астрономических данных, до обработки санкранти (солнечных переходов по зодиаку) и финальной сортировки событий.

**Влияние:** в период существования этого коммита календарь не содержал событий санкранти и события могли быть в неотсортированном порядке. Изменение было откатано другим автором.
